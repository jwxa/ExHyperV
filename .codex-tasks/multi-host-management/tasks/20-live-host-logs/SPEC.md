# Issue #20：实时展示当前宿主的脱敏日志

## 目标

让“主机连接”页日志 Tab 实时显示当前选中宿主的诊断、会话、重连、配置和 VM 操作日志。磁盘与 UI 必须消费同一个已脱敏、不可变的结构化条目；内存历史按宿主封顶，切换宿主立即切换日志范围，并提供符合阅读习惯的自动跟随、暂停和“回到最新”交互。

## 已确认测试边界

- 结构化条目：包含 `HostId`、时间、级别、来源、错误分类和已脱敏消息。
- 单次脱敏：原始输入只在 `AppLog` 入口转换一次；滚动文件与实时 Feed 接收同一个条目。
- Feed 隔离：快照和订阅按 `HostId` 路由，每宿主默认只保留最近 2,000 条。
- 诊断流：每个诊断步骤完成时立即发布，不等待完整报告。
- 页面选择：日志集合只对应当前选中宿主，切换选择后旧订阅不能继续写入页面。
- 滚动交互：默认跟随最新；用户离开底部后暂停；点击图标按钮恢复并滚至最新。
- 磁盘兼容：继续写入程序目录 `logs`，`ExHyperV.log` 与 `ExHyperV.1.log` 各不超过 100 MiB。

## 交付范围

1. 新增不可变 `AppLogEntry` 和按宿主有界历史/订阅的 `IHostLogFeed`。
2. 重构 `AppLog` 与滚动文件写入器，使磁盘和 Feed 共享同一脱敏条目。
3. 为诊断、会话、重连、配置和 VM 操作补齐明确宿主上下文，诊断按步骤流式发布。
4. 将日志 Tab 改为可虚拟化条目列表，并接入当前宿主过滤和订阅生命周期。
5. 实现自动跟随、用户滚动暂停和“回到最新”图标按钮。

## 非目标

- 不加入远程日志上传、集中日志服务器、全文检索或复杂查询。
- 不改变现有磁盘目录、文件名、100 MiB x 2 和 UTF-8 无 BOM 策略。
- 不实现诊断结果驱动的设置修复；属于 #21。
- 不升级 `SSH.NET` 或处理既有构建警告。
- 不对 `10.0.0.6` 执行配置修改、VM 写入或故障注入。

## 验收

- 磁盘和 UI 收到同一脱敏结果，密码、令牌、凭据对象及敏感字段名和值均不可见。
- 实时条目包含宿主、时间、级别、来源和错误分类，且诊断步骤逐条到达。
- 切换选中宿主立即更换日志范围；旧宿主后续条目不进入当前页面。
- 每宿主历史默认封顶 2,000 条，宿主之间互不挤占。
- 默认跟随最新；用户向上滚动后新条目不改变阅读位置；点击“回到最新”恢复。
- 现有滚动文件、确定性测试、Release 构建、UTF-8 无 BOM、凭据模式和差异检查通过。
