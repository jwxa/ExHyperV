# Issue #15：宿主身份与多会话注册表

## 目标

建立多宿主模型的最小公共边界：稳定的 `HostId`、宿主范围内的 `VmKey`、不可变的注册表快照，以及固定本机加多台远程宿主并存的注册表行为。

## 已确认测试边界

- `HostId`：`HostId.Local` 明确表示本机；远程身份只由 `HostProfile.Id` 构造。
- `VmKey`：由 `HostId + VmId` 唯一确定，两个宿主上的相同 VM GUID 必须是不同键。
- `IHostSessionRegistry.Current`：通过完整不可变快照观察本机和远程会话，不测试内部字典或锁。
- 注册表状态事件：只发布前后完整快照，并保持稳定宿主顺序。
- 现有 `IActiveHostSessionCoordinator`：在迁移阶段继续通过全部基线测试。

这些边界来自用户已接受的 `doc/multi-host-management-design.md`，不新增实现细节型测试。

## 交付范围

1. 身份值对象及其参数校验。
2. 会话条目与注册表快照，启动时本机固定存在且排在第一位。
3. 最小多会话注册表，可原子加入两台远程宿主且互不替换。
4. 每宿主独立代次，目标宿主更新不能改变其他宿主代次。
5. 保持现有单活动宿主兼容路径和全部确定性测试通过。

## 非目标

- 不在本 Issue 修改 VM 页面或增加宿主分组 UI。
- 不迁移 VM 读写操作；显式操作路由属于 #16/#17。
- 不实现写租约、掉线重连和主动断开事务；分别由后续 Issue 完成。
- 不修改远程计算机设置或访问受控宿主。

## 验收

- 本机身份和本机会话始终存在。
- 本机、远程 A、远程 B 可同时出现在一个不可变快照中。
- A 的状态或代次变化不改变 B；旧 A 代次不能应用到新 A。
- 同 VM GUID 在不同宿主下得到不同 `VmKey`。
- 确定性测试全部通过，新增文本为 UTF-8 无 BOM，`git diff --check` 通过。
