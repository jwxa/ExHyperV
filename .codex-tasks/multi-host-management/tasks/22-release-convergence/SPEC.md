# Issue #22：收缩旧活动宿主模型并完成发布验收

## 目标

删除产品仍可调用的全局活动宿主兼容路径，使本机与所有远程宿主只通过 `IHostSessionRegistry`、显式 `HostId` 和 `VmKey` 路由。统一主机/虚拟机界面的主题资源，更新最终用户文档，并以确定性测试、Release/WPF 构建和受控宿主只读验收证明多宿主功能可发布。

## 已确认边界

- 删除 `IActiveHostSessionCoordinator`、全局 `ActiveHostSessions.Current`、旧 VM 操作适配器和无 `HostId` 的控制台入口。
- 每宿主内部会话引擎继续复用现有连接、写租约、代次、旧数据和重连实现；本任务不重写已验证协议。
- 本机专属页面固定使用注册表中的 `HostId.Local`，远程选择不再禁用本机导航或改变本机写入目标。
- 受控验收使用 `HostSessionRegistry` 与 `HostOperationRouter`，并显式证明主动断开只移除目标远程宿主。
- TCP 2179 不可用但 WMI/DCOM 可用是通过的降级场景，不作为整体诊断失败。
- 不执行远程配置、回滚、VM 写入或故障注入，除非对应环境开关获得精确中文 `确认`。
- 不恢复已被用户停止的桌面自动化；视觉门禁必须如实记录其当前证据状态。

## 交付范围

1. 建立唯一的多宿主注册表服务入口，迁移产品调用方并删除全局活动宿主接口。
2. 删除或改写只验证单活动宿主的 VM、控制台和会话测试。
3. 迁移集成运行器到显式宿主路由，覆盖本机 + 远程、第二远程并行和主动断开。
4. 移除本迭代界面的硬编码黑色/灰色，复用现有主题资源并补 UI 契约。
5. 更新 README、隐私说明和远程宿主用户指南。
6. 完成自动化、Release/WPF、UTF-8 无 BOM、敏感字面量、主题颜色和差异检查；运行 `10.0.0.6` 只读验收。

## 非目标

- 不更换 WMI/DCOM、TCP 2179、Windows Credential Manager 或 PowerShell 配置协议。
- 不自动连接已保存远程宿主，不增加宿主发现或后台静默修复。
- 不借收口任务重写 1000 行级的每宿主连接/重连引擎。
- 不在无精确授权时运行危险集成开关。

## 验收

- GitHub #22 的 9 条验收标准均有当前实现和证据。
- 生产代码不再通过全局活动宿主选择 VM、控制台或本机专属操作目标。
- 启动快照仅含本机；连接与断开均只影响显式远程 `HostId`。
- 本机 + 两远程的并行、隔离、重连和断开由确定性测试覆盖。
- 受控宿主完成真实诊断、VM 读取、控制台能力验证和主动断开；危险开关全部保持关闭。
- 文档、主题、构建、测试、XAML、编码和差异门禁通过；未执行的人工视觉项明确标注。
