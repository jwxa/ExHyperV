# Issue #21：按诊断结果提供设置检查与修复

## 目标

移除长期可见的“配置预检”，仅在当前选中远程宿主的最新诊断表明存在可安全检查的问题时显示“检查并修复设置”。工作流必须先只读检测和展示完整证据/预览，只有精确输入中文 `确认` 后才能复用现有最小修改、回滚和复诊流水线。

## 已确认测试边界

- 入口判定：纯诊断决策将可检查问题、不可自动处理问题和无问题分开；无可处理发现时入口不可见。
- 上下文绑定：修复上下文同时绑定配置 ID、IPv4 和诊断开始时间；选择、编辑或新诊断使旧上下文失效。
- 只读阶段：打开入口只运行 `HostPreflightPipeline`，远程命令执行器调用数保持为零。
- 检测证据：预检日志带时间逐条到达，最终报告仍保留完整日志。
- 网络选择：Public 网络不默认选择或修改，必须由用户从候选列表明确选择并勾选改为 Private。
- 确认门：任何非精确 `确认` 均执行零修改；现有编译器继续限制账户、规则和 CIDR 范围。
- 完成复检：执行后沿用配置流水线重新诊断 WMI/DCOM 和 TCP 2179，并刷新目标宿主通道。
- 不可处理结果：只显示中文引导，不提供自动修改入口。

## 交付范围

1. 新增诊断到修复入口的纯决策与版本上下文。
2. 将常驻“配置预检”替换为按需“检查并修复设置”，修复 Tab 仅在工作流打开后可见。
3. 让预检日志在步骤产生时逐条更新，并保持最终完整证据。
4. 应用前校验当前宿主和最新诊断仍匹配打开时上下文。
5. 复用并验证现有预检、最小变更、精确确认、回滚和复诊实现。

## 非目标

- 不重写 PowerShell 配置命令、回滚脚本或 Windows WMI 适配器。
- 不尝试自动修复错误密码、主机离线、无效 IPv4、Hyper-V 命名空间缺失或未知错误。
- 不执行 `10.0.0.6` 的真实配置、回滚、VM 写入或故障注入。
- 不引入主机发现、自动修复或后台静默修改。

## 验收

- GitHub #21 的 9 条验收标准均有实现和确定性证据。
- 页面不再含常驻“配置预检”；入口、Tab 和上下文不会指向旧宿主或旧诊断。
- 预检日志逐条可见，完整变更清单和 Public 网络显式选择保持可审查。
- 非精确确认零修改；精确确认只走现有最小变更并产出精确回滚材料和复诊结果。
- 确定性测试、Release 构建、UTF-8 无 BOM、敏感模式、主题颜色和差异检查通过。
