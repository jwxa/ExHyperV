# Issue #17：多台远程宿主与隔离操作

## 目标

用户在本机始终在线时，可以继续连接第二台及更多远程宿主；虚拟机页面按成功连接顺序显示全部远程分组，每组独立刷新，选择、读取、写入和控制台始终保留所属 `HostId`。

## 已确认测试边界

- `IHostSessionRegistry`：本机、远程 A、远程 B 的不可变快照与连接顺序。
- `IHostOperationRouter`：A/B 独立 WMI 上下文、写租约、代次和旧结果拒绝。
- VM 分组生命周期：每个已连接宿主独立刷新，慢宿主不阻塞其他组。
- 选择域：跨组选择替换原选择，批量目标只能来自同一 `HostId`。
- `VmKey`：同名或同 GUID VM 在不同宿主中保持不同身份。

## 交付范围

1. VM 页面从注册表快照加载全部已连接宿主，本机固定第一，远程按成功连接顺序追加。
2. 新连接的每台远程宿主创建独立 VM 分组与监控循环；手动刷新并行处理各组。
3. 远程 A 的慢查询、写租约、连接丢失或旧代次结果不阻塞或污染远程 B。
4. 将跨组选择规则收敛到可测试状态；视觉选择与批量命令保持单宿主范围。
5. 保持现有统一详情模板、能力门控、控制台路由和本机性能采集不变。

## 非目标

- 不在本 Issue 完成旧数据展示与独立自动重连交互；属于 #18。
- 不实现主动断开和控制台关闭确认；属于 #19。
- 不实现实时日志与按需设置修复；属于 #20/#21。
- 不支持跨宿主批量命令或跨宿主事务。

## 验收

- 本机、远程 A、远程 B 同时显示，本机固定第一，远程顺序稳定。
- 每台宿主独立刷新 VM 列表和运行状态，A 的慢查询不阻塞 B。
- A 的写租约不阻止 B 读写；A 的旧结果不能更新 A 新会话或 B。
- 同名或同 GUID VM 仍由 `VmKey` 区分，操作目标不串组。
- 选择另一宿主的 VM 会清除原宿主选择，批量命令只收到单一宿主目标。
- 确定性测试、Release 构建、UTF-8 无 BOM 和差异检查通过。
