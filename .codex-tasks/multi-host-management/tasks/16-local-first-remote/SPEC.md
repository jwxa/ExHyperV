# Issue #16：本机与首台远程宿主并列管理

## 目标

用户完成一次最新诊断后连接远程宿主，虚拟机页面保留本机分组并新增该远程宿主分组；每项已启用 VM 操作由 VM 所属 `HostId` 决定目标，不再由页面选中宿主或全局活动宿主决定。

## 已确认测试边界

- `IHostOperationRouter`：通过显式 `HostId` 验证本机/远程 WMI 上下文、写租约和旧结果拒绝。
- `IHostSessionRegistry`：通过最新诊断生成连接请求，成功后完整快照新增远程会话。
- `HostVmGroupViewModel`：通过公开组集合验证本机固定第一、首台远程追加及组内 VM 归属。
- VM 页面 XAML：验证宿主分组标题、共享列表项样式和按 VM 所属宿主选择详情能力。

这些接缝已由 `doc/multi-host-management-spec.md` 和 `doc/multi-host-management-design.md` 确认。

## 交付范围

1. 建立显式 `HostId` 的 VM 读写路由，复用已有连接丢失分类、写租约和脱敏处理。
2. 将注册表作为应用级共享运行时，并让主机连接页在最新诊断成功后加入远程会话。
3. 建立宿主 VM 分组；启动时本机组始终存在，连接首台远程后并列显示。
4. VM 列表加载、电源操作及已启用控制台入口使用 VM 所属宿主身份。
5. 本机和远程复用现有主题、列表项和状态视觉；永久不支持项不在远程详情中展示。

## 非目标

- 不在本 Issue 完成两台远程宿主的并发刷新和跨组多选；属于 #17。
- 不实现掉线旧数据的完整 UI 与独立自动重连交互；属于 #18。
- 不实现带控制台窗口确认的主动断开事务；属于 #19。
- 不实现实时日志和按诊断结果修复；属于 #20/#21。

## 验收

- 新启动 VM 页面始终包含本机分组。
- 对首台远程宿主完成最新诊断并连接后，本机组不消失，远程组新增并加载其 VM。
- 本机读写使用本机 WMI 上下文；远程读写使用该宿主连接上下文。
- 远程 VM 命令不能误操作本机，同名或同 GUID VM 仍由 `VmKey` 区分。
- 不再展示“切回本机”入口。
- 确定性测试、Release 构建、UTF-8 无 BOM 和差异检查通过。
