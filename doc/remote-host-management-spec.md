# ExHyperV 局域网远程主机管理规格

> 迭代说明：本文记录已实现的第一阶段“单活动宿主”基线。2026-08-15 已确认的后续规格见 [multi-host-management-spec.md](multi-host-management-spec.md)，详细设计见 [multi-host-management-design.md](multi-host-management-design.md)；其中“本机固定 + 多台远程宿主并行”的决策在实施后取代本文的单活动宿主限制，现有协议、安全和配置约束继续有效。

## Problem Statement

ExHyperV 当前以本机 Hyper-V 为默认运行环境。尽管底层 WMI 封装已经具备创建远程连接上下文的基础能力，大量服务仍默认或显式使用本机上下文，虚拟机控制台也固定连接本机 `localhost:2179`。用户无法在 ExHyperV 中保存多台局域网 Hyper-V 主机、检测远程主机是否满足连接条件、切换当前管理目标，或清楚地区分“管理功能可用”和“控制台可用”。

这使用户不得不依赖远程桌面、手工 PowerShell 或其他管理工具操作局域网中的 Hyper-V 主机。发生权限、防火墙、网络配置文件或 TCP 2179 问题时，用户也缺少可解释的中文诊断结果和可回滚的配置方法。

## Solution

为 ExHyperV 增加“主机连接”模块，使用 WMI/DCOM 作为远程 Hyper-V 管理通道，使用 TCP 2179 作为虚拟机控制台通道。用户可以保存多台 IPv4 主机配置，但同一时刻只有一台活动宿主。应用每次启动都以本机作为活动宿主，不会因为上一次远程连接或连接失败而自动切换管理目标。

模块提供持久可见的活动宿主状态、主机配置列表、连接诊断、能力矩阵、自动重连状态和详细中文日志。WMI/DCOM 与 TCP 2179 分别检测，允许出现“管理可用、控制台不可用”的部分连接状态。

对尚未配置好的远程主机，提供中文配置向导。向导先检测并展示建议，用户确认目标账户、网络配置文件、允许访问的 IPv4 CIDR 和具体系统修改后，必须输入精确的“确认”才能执行。所有修改都生成回滚脚本，并记录到滚动日志中。

## User Stories

1. 作为 ExHyperV 用户，我希望保存多台局域网 Hyper-V 主机，以便以后快速重新连接。
2. 作为 ExHyperV 用户，我希望为每台主机设置易识别的配置名称，以便区分用途相近的服务器。
3. 作为 ExHyperV 用户，我希望通过 IPv4 地址添加远程主机，以便避免第一版引入主机名解析和 IPv6 的额外不确定性。
4. 作为 ExHyperV 用户，我希望应用启动时始终连接本地宿主，以便启动行为稳定且不会意外操作远程机器。
5. 作为 ExHyperV 用户，我希望同一时刻只有一台活动宿主，以便所有页面对当前操作目标保持一致理解。
6. 作为 ExHyperV 用户，我希望活动宿主的名称、IPv4 地址和状态持续可见，以便在执行操作前确认目标。
7. 作为 ExHyperV 用户，我希望选择保存的主机只查看详情而不立即切换活动宿主，以便先检查状态再决定是否连接。
8. 作为 ExHyperV 用户，我希望切换活动宿主前看到明确确认，以便避免误切换。
9. 作为 ExHyperV 用户，我希望切换主机是原子的，以便页面不会同时显示两个宿主的数据。
10. 作为 ExHyperV 用户，我希望存在进行中的写操作时禁止切换宿主，以便避免操作落到错误目标或产生不一致状态。
11. 作为 ExHyperV 用户，我希望切换期间暂时禁用写操作，以便所有页面在新宿主完成加载前保持安全。
12. 作为 ExHyperV 用户，我希望危险确认同时显示宿主名和虚拟机名，以便明确即将影响的具体对象。
13. 作为 ExHyperV 用户，我希望默认使用当前 Windows 身份连接远程主机，以便域环境和已授权账户无需重复输入凭据。
14. 作为 ExHyperV 用户，我希望当前 Windows 身份无需额外决策或配置，以便符合项目已有身份处理方式。
15. 作为 ExHyperV 用户，我希望当前身份失败时可以指定本地账户或域账户，以便连接工作组或独立主机。
16. 作为 ExHyperV 用户，我希望明确选择是否记住指定凭据，以便在便利性和本机安全之间自行决定。
17. 作为 ExHyperV 用户，我希望记住的密码只保存到 Windows 凭据管理器，以便配置文件和日志不包含明文密码。
18. 作为 ExHyperV 用户，我希望可以保存多个凭据关联的主机配置，以便管理不同权限边界的宿主。
19. 作为 ExHyperV 用户，我希望编辑主机配置时不会在界面上回显已保存密码，以便避免凭据泄露。
20. 作为 ExHyperV 用户，我希望删除主机配置时可同步删除其凭据引用，以便不留下无主凭据。
21. 作为 ExHyperV 用户，我希望连接前检测 IPv4 可达性，以便快速识别基础网络问题。
22. 作为 ExHyperV 用户，我希望单独检测 WMI/DCOM，以便知道 Hyper-V 管理功能是否可用。
23. 作为 ExHyperV 用户，我希望 WMI 检测验证 `root\virtualization\v2`，以便确认不是只有端口开放而实际无权管理 Hyper-V。
24. 作为 ExHyperV 用户，我希望单独检测 TCP 2179，以便知道虚拟机控制台是否可用。
25. 作为 ExHyperV 用户，我希望看到每项检测的结果、耗时和中文解释，以便定位失败阶段。
26. 作为 ExHyperV 用户，我希望看到详细的按时间排序检测日志，以便复现或提交问题。
27. 作为 ExHyperV 用户，我希望 WMI/DCOM 成功但 TCP 2179 失败时仍可进入远程管理，以便不因控制台故障失去其他功能。
28. 作为 ExHyperV 用户，我希望部分连接状态明确显示“管理可用、控制台不可用”，以便理解实际影响。
29. 作为 ExHyperV 用户，我希望控制台不可用时“打开控制台”保持可见但置灰，以便知道功能存在以及为什么不可用。
30. 作为 ExHyperV 用户，我希望远程宿主不支持的功能保持可见并显示原因，以便区分“暂不支持”和“界面缺失”。
31. 作为 ExHyperV 用户，我希望本地专属功能在远程活动宿主上被禁用，以便不把本机设备错误应用到远程宿主。
32. 作为 ExHyperV 用户，我希望每个页面根据统一能力状态决定可读、可写或禁用，以便得到一致体验。
33. 作为 ExHyperV 用户，我希望远程连接中断时当前数据标记为旧数据，以便不误认为它仍然实时。
34. 作为 ExHyperV 用户，我希望连接中断后立即禁用写操作，以便避免对失效会话继续提交变更。
35. 作为 ExHyperV 用户，我希望 ExHyperV 自动重连当前远程宿主，以便短暂网络波动后自动恢复工作。
36. 作为 ExHyperV 用户，我希望自动重连采用有上限的指数退避，以便兼顾恢复速度和网络负载。
37. 作为 ExHyperV 用户，我希望看到重连次数和下一次尝试时间，以便理解应用正在做什么。
38. 作为 ExHyperV 用户，我希望远程宿主断线时不自动切回本机，以便避免后续操作静默落到错误宿主。
39. 作为 ExHyperV 用户，我希望重连成功后重新刷新宿主快照和功能能力，以便恢复到可信状态。
40. 作为 ExHyperV 用户，我希望手动停止重连或主动切换到其他主机，以便在长期故障时继续工作。
41. 作为 ExHyperV 用户，我希望配置向导先检测远程主机而不立即修改，以便先审查环境和建议。
42. 作为 ExHyperV 用户，我希望配置向导全程使用中文，以便准确理解系统级修改。
43. 作为 ExHyperV 用户，我希望向导列出每个检测项的详细日志，以便知道建议基于什么事实。
44. 作为 ExHyperV 用户，我希望向导列出远程主机上已启用的本地用户，以便选择授权账户。
45. 作为 ExHyperV 用户，我希望也能手动输入域账户，以便域环境不受本地用户列表限制。
46. 作为 ExHyperV 用户，我希望向导只授予 `Hyper-V Administrators` 和 `Remote Management Users` 组成员资格，以便遵循最小权限。
47. 作为 ExHyperV 用户，我希望向导不自动授予本地管理员权限，以便避免不必要的权限扩大。
48. 作为 ExHyperV 用户，我希望仅在工作组、本地管理员账户且策略缺失时设置 `LocalAccountTokenFilterPolicy=1`，以便避免无条件降低远程 UAC 限制。
49. 作为 ExHyperV 用户，我希望向导检测所选网络适配器的网络配置文件，以便识别 Public 配置造成的限制。
50. 作为 ExHyperV 用户，我希望网络当前为 Public 时由我确认是否改为 Private，以便不发生静默网络安全变更。
51. 作为 ExHyperV 用户，我希望从检测到的网络列表中选择要修改的网络，以便多网卡主机不会改错接口。
52. 作为 ExHyperV 用户，我希望选择允许访问的 IPv4 CIDR，以便防火墙规则只开放给需要的局域网范围。
53. 作为 ExHyperV 用户，我希望可以从检测到的私有网段中勾选 CIDR，以便减少输入错误。
54. 作为 ExHyperV 用户，我希望可以手工补充合法 IPv4 CIDR，以便支持未自动检测到的管理网段。
55. 作为 ExHyperV 用户，我希望向导启用 Windows 内置 WMI 和 Hyper-V 防火墙规则组，以便复用系统已有能力。
56. 作为 ExHyperV 用户，我希望向导只为 TCP 2179 创建独立的 ExHyperV 入站规则，以便规则来源和用途清晰。
57. 作为 ExHyperV 用户，我希望向导不修改全局动态 RPC 端口范围，以便不扩大系统级网络变更范围。
58. 作为 ExHyperV 用户，我希望应用前看到所有建议修改的完整清单，以便逐项审查。
59. 作为 ExHyperV 用户，我希望必须输入精确的“确认”才能执行配置，以便防止误触。
60. 作为 ExHyperV 用户，我希望配置完成后自动重新检测 WMI/DCOM 和 TCP 2179，以便验证修改是否有效。
61. 作为 ExHyperV 用户，我希望无论配置成功或部分失败都生成回滚脚本，以便恢复已执行的修改。
62. 作为 ExHyperV 用户，我希望回滚脚本只撤销本次向导实际做出的变更，以便不破坏原有配置。
63. 作为 ExHyperV 用户，我希望配置执行的每一步都有中文日志和明确结果，以便审计和排错。
64. 作为 ExHyperV 用户，我希望应用日志位于 ExHyperV 可执行文件目录下的 `logs` 目录，以便便携部署时容易查找。
65. 作为 ExHyperV 用户，我希望当前日志文件最多为 100 MB，以便日志不会无限增长。
66. 作为 ExHyperV 用户，我希望保留一份最多 100 MB 的上一轮日志，以便问题发生在轮转前后时仍可追溯。
67. 作为 ExHyperV 用户，我希望日志总量约束在 200 MB 内，以便控制磁盘占用。
68. 作为 ExHyperV 用户，我希望日志记录主机、通道、状态转换和错误分类，以便支持完整诊断。
69. 作为 ExHyperV 用户，我希望日志永远不记录密码、凭据令牌或其他秘密，以便分享日志时更安全。
70. 作为 ExHyperV 维护者，我希望所有远程操作通过统一的活动宿主会话上下文，以便现有功能逐步获得远程支持而不重复连接逻辑。
71. 作为 ExHyperV 维护者，我希望 WMI 连接、TCP 探测、凭据存储、配置执行和日志记录都通过窄接口接入，以便可以独立测试和替换。
72. 作为 ExHyperV 维护者，我希望服务层不再自行决定本机或远程目标，以便活动宿主成为唯一事实来源。
73. 作为 ExHyperV 维护者，我希望连接状态机具有明确、可测试的状态和转换，以便处理部分连接、断线和重连。
74. 作为 ExHyperV 维护者，我希望每次写操作携带不可变的宿主会话标识，以便宿主切换后拒绝旧会话提交。
75. 作为 ExHyperV 维护者，我希望配置文件只保存非敏感主机元数据和凭据引用，以便数据格式可维护且不泄密。
76. 作为 ExHyperV 维护者，我希望远程模块复用现有 Fluent/WPF-UI 视觉语言，以便新模块与现有页面一致。
77. 作为 ExHyperV 维护者，我希望远程能力可以按页面逐步接入，以便第一阶段不需要一次性重写全部服务。
78. 作为 ExHyperV 支持人员，我希望用户能够导出或定位详细日志与回滚脚本，以便远程协助时获得可重现证据。

## Implementation Decisions

- 第一版连接协议固定为 WMI/DCOM 管理通道加 TCP 2179 Hyper-V 控制台通道，不引入 WinRM、PowerShell Remoting、代理服务或自定义 RPC。
- 第一版远程地址只接受 IPv4。主机名、DNS 发现、IPv6 和自动扫描局域网不属于本规格。
- 增加“活动宿主会话协调器”作为唯一运行时事实来源。它负责选中配置、活动宿主、会话代次、连接状态、能力状态、旧数据标记、重连计划和写操作门控。
- 用户可以保存多个主机配置，但只能有一个活动宿主。选中列表项与切换活动宿主是两个独立动作。
- 应用每次启动创建本地活动会话，不恢复上次远程活动宿主。保存的远程配置仍保留在列表中。
- 宿主切换采用准备、确认、冻结写入、建立新会话、加载基础快照、原子提交、释放旧会话的流程。任一步失败则保持原活动宿主，不发布半完成状态。
- 活跃写操作存在时不允许开始宿主切换。已进入切换冻结阶段后，不再接受新的写操作。
- 每个写操作捕获不可变的会话代次；完成前若活动会话已改变，则结果不得写回新会话的 UI 状态。
- 远程连接默认使用当前 Windows 身份。指定用户名和密码仅作为用户主动选择的回退方式。
- 保存显式凭据时，密码写入 Windows 凭据管理器；应用配置只保存稳定的凭据目标引用。密码不写入 XML、日志、异常消息或遥测。
- WMI 连接上下文需要支持两种远程身份模式：不显式设置用户名密码以使用当前 Windows 身份，以及从凭据适配器解析显式凭据。现有远程上下文只接受用户名和密码的接口需要扩展。
- 现有 WMI 统一入口继续作为管理调用边界，但其默认上下文由活动宿主会话提供。显式写死本地上下文的调用需要按远程能力范围逐步迁移。
- WMI/DCOM 检测必须执行对 `root\virtualization\v2` 的实际查询，而不是只做端口探测。
- TCP 2179 检测和控制台连接使用活动宿主 IPv4。控制台连接设置不再固定为 `localhost`。
- WMI/DCOM 与 TCP 2179 分别建模，不使用单一布尔“已连接”。至少支持本地已连接、远程连接中、全部可用、部分可用、重连中、断开和失败等用户可见状态。
- WMI 可用且 TCP 2179 不可用时，远程会话进入部分可用状态。管理能力保持启用，控制台能力禁用并显示原因。
- 能力矩阵由活动宿主类型、通道状态和已实现范围共同计算。尚不支持的远程功能必须保持可见并提供置灰原因。
- 连接中断后保留最后一次成功快照，但标记为旧数据并立即禁用写操作。
- 自动重连采用带上限的指数退避，并提供当前次数和下一次尝试时间。具体退避常量可在实现阶段确定，但必须可取消且不得形成并发重连。
- 重连期间不得静默切换回本机。用户可以主动选择本机或其他已保存主机。
- 重连成功后必须重新验证两个通道、刷新基础宿主快照并重新计算能力，然后才解除旧数据和写入禁用状态。
- 活动宿主状态必须在应用主工作区持续可见，至少展示名称、IPv4 地址、连接状态和身份模式。
- 危险操作确认必须同时展示活动宿主名称和虚拟机名称；批量操作还必须展示目标数量。
- 主机连接模块采用现有 WPF-UI/Fluent 视觉语言，包括 Mica 背景、紧凑工作区、8 像素以内圆角、Segoe 字体、Windows 蓝强调色和图标按钮。
- HTML 原型中的 A/B/C 布局用于比较信息架构，不构成最终布局承诺。最终 WPF 页面应保留原型已验证的工作流和状态呈现，并在实施前选定一种布局。
- 配置向导是显式的检测、审查、确认、应用流程。检测步骤只读，不得因打开向导而修改远程主机。
- 配置向导输出完整中文预检日志和拟执行修改列表。
- 账户步骤列出启用的本地用户，同时允许手工输入域账户。
- 向导只将选定账户加入 `Hyper-V Administrators` 和 `Remote Management Users`。不创建用户、不重置密码、不自动加入 Administrators。
- 仅当主机处于工作组、选择的是已存在的本地管理员账户且策略缺失时，建议并设置 `LocalAccountTokenFilterPolicy=1`。不满足条件时不展示为待执行修改。
- 网络配置文件为 Public 时，向导展示可选网络列表；只有用户勾选并在最终步骤确认后才改为 Private。
- 用户必须选择一个或多个允许访问的 IPv4 CIDR。输入需要规范化、去重并拒绝非法或非 IPv4 CIDR。
- 防火墙配置复用 Windows 内置 WMI 和 Hyper-V 入站规则，并创建用途明确的 TCP 2179 入站规则。若 `ActiveStore` 缺少内置规则，但 `SystemDefaults` 中存在对应规则，则只按预检得到的精确 `InstanceID` 逐条复制到 `PersistentStore`；禁止使用规则组、通配符、`Any` 选择器或防火墙整库重置。TCP 2179 规则的远程地址限制为用户选择的 CIDR。
- 向导不得修改全局动态 RPC 端口范围。
- 最终应用前必须输入完全匹配的中文“确认”。其他大小写、空格或相似字符均不得通过确认门。
- 配置执行采用逐步结果记录。只要开始产生修改，就必须生成与实际执行步骤对应的回滚脚本；部分失败也不能省略回滚脚本。
- 回滚脚本应使用 UTF-8 编码、中文说明和可重复执行的保护逻辑，仅撤销本次确实发生的修改。默认规则复制失败时应补偿已复制项；人工回滚删除复制规则前，必须先验证整批规则仍由本地 `PersistentStore` 所有，并与 `SystemDefaults` 的规则状态及关联过滤器一致，发现漂移时不得部分删除。
- 日志目录固定为 ExHyperV 可执行文件所在目录下的 `logs`。若目录不可创建或不可写，应用继续运行并向用户明确报告日志不可用，不回退到不透明位置。
- 主日志为 `ExHyperV.log`，单文件上限 100 MB；轮转后保留 `ExHyperV.1.log`，其上限同为 100 MB；不保留更多历史文件。
- 日志使用 UTF-8 无 BOM，记录中文用户语义、时间、级别、组件、宿主标识、会话代次和错误分类。密码、令牌、凭据对象、完整安全描述符和其他秘密必须在写入前清理。
- 主机配置可继续放入现有应用配置体系，但远程主机集合应有独立版本字段，支持后续数据迁移并与界面设置解耦。
- 第一阶段优先让虚拟机查询、基本生命周期管理和控制台使用活动宿主；对依赖本机硬件、注册表、HCS、设备枚举或本地文件系统的功能先显示为远程不支持，除非实现明确的远程适配器。

## Testing Decisions

- 核心自动化测试只建立一个高层验收边界：活动宿主会话协调器。测试通过其公开命令和状态快照验证外部行为，不断言内部缓存、线程、WMI 对象或具体类调用次数。
- WMI/DCOM、TCP 探测、凭据管理器、配置执行器、时钟、重连调度和日志写入作为窄适配器注入协调器。测试使用确定性替身驱动成功、失败、超时、取消和部分成功。
- 仓库当前没有测试项目或既有自动化测试先例。本功能需要建立最小独立测试项目；测试命名围绕用户可观察行为，而非私有方法。
- 必测连接场景包括：本机启动、当前身份远程成功、显式凭据成功、认证失败、WMI 成功且 2179 失败、WMI 失败且 2179 成功、两通道均失败和用户取消。
- 必测宿主切换场景包括：成功原子切换、准备失败保持原宿主、活跃写操作阻止切换、切换冻结后拒绝新写操作、旧会话异步结果不能污染新会话。
- 必测断线场景包括：数据变旧、写操作禁用、指数退避、同一时间只有一个重连任务、用户取消、重连成功恢复能力、长期失败不切回本机。
- 必测能力场景包括：控制台因 2179 失败而禁用、远程本地设备功能置灰、状态原因可展示、恢复连接后能力重新计算。
- 必测凭据场景包括：当前身份不读取凭据管理器、显式凭据只通过引用解析、配置和日志无明文密码、删除配置清理凭据引用、凭据缺失产生可解释错误。
- 配置向导在高层测试中覆盖：检测绝不修改、Public 到 Private 必须显式选择、账户最小授权、条件性令牌过滤策略、CIDR 校验、精确“确认”门、`SystemDefaults` 精确规则恢复、复制中途失败补偿、回滚漂移拒删、部分失败生成回滚、成功后重新检测。
- 日志测试通过临时目录验证：创建日志目录、100 MB 边界触发单次轮转、仅保留两个文件、进程重启后继续写入、并发写入不产生破损记录、敏感字段被清理。
- WMI 适配器保留少量 Windows 集成测试，验证当前身份和显式凭据能连接受控 Hyper-V 测试宿主并查询实际命名空间。这些测试应标记为需要 Windows/Hyper-V 环境，不阻塞普通开发机的快速测试。
- TCP 2179 使用受控监听器和不可达端点分别验证成功、拒绝、超时和取消，不依赖公网。
- WPF UI 使用 ViewModel 状态测试覆盖命令启用、置灰原因、状态文本和确认数据。只对最关键工作流保留人工验收，不使用像素级截图作为业务正确性测试。
- HTML 原型作为人工验收参考，重点核对：活动宿主持久可见、添加与连接对话框、部分连接、自动重连、功能置灰、配置向导、日志页面和窄窗口无重叠。
- 完成条件包括在两台受控 Windows 主机间执行一次端到端验收：保存配置、当前身份连接、切换活动宿主、管理虚拟机、打开 2179 控制台、模拟断线、自动重连以及生成并执行一次回滚脚本。

## Out of Scope

- IPv6、主机名/DNS 连接、mDNS、Active Directory 自动发现和局域网扫描。
- 同时连接或并排管理多台活动宿主。
- 集群、故障转移群集、Hyper-V Replica、实时迁移和跨宿主批量编排。
- WinRM、PowerShell Remoting、SSH、代理服务或自定义后台服务作为管理协议。
- 修改 Windows 全局动态 RPC 端口范围。
- 自动创建远程用户、修改账户密码、加入 Administrators 或扩大到本规格以外的权限组。
- 无确认地将网络配置文件从 Public 改为 Private。
- 自动开放任意来源地址、全网段或公网访问 TCP 2179。
- 将密码或令牌保存到应用配置、回滚脚本或日志。
- 对所有现有本机专属功能在第一阶段实现远程等价能力。
- 远程 USB 转发、远程本地设备枚举以及基于远程宿主物理设备的 PCIe 交互。
- 改变现有 Hyper-V 虚拟机控制台协议、增强会话语义或 RDP 控件实现。
- 云端同步主机配置或凭据。
- 超过两份、总量超过约 200 MB 的内建日志保留策略。
- 最终确定 HTML 原型 A/B/C 中的具体布局；布局选择属于后续 UI 实施决策，不改变本规格的行为合同。

## Further Notes

- 当前代码已经具备集中式 WMI API 和远程 `WmiContext` 雏形，因此实施应扩展现有入口，而不是建立第二套 WMI 客户端。
- 当前远程上下文构造要求用户名和密码，尚不能表达“远程主机 + 当前 Windows 身份”；这是实现默认身份策略时需要补齐的关键接口。
- 当前仍有少量服务直接获取本地 ManagementScope，且控制台服务器固定为 localhost。它们是第一阶段迁移审计的重点。
- 当前仓库没有自动化测试项目。新测试项目应保持小而高层，避免为每个现有服务制造独立 mock 层。
- UI 原型已验证三种信息架构以及桌面、窄窗口和配置向导流程。原型中的示例数据只用于展示状态层级，不构成产品默认数据。
- 现有隐私政策声明所有操作严格在本机执行。远程主机功能发布前必须同步修订隐私政策和 README，准确说明局域网连接、配置存储、凭据管理器和本地日志行为。
- 规格实施应遵循 KISS：统一活动宿主上下文，不在页面内复制连接判断；遵循 YAGNI：第一版只做 IPv4、单活动宿主和既定协议；遵循 DRY：诊断、能力计算和错误映射集中复用；遵循 SOLID：协调器只负责编排，系统交互通过专一适配器隔离。
