# ExHyperV 多宿主会话与分组虚拟机管理规格

## Problem Statement

ExHyperV 第一阶段远程管理使用单一活动宿主模型。用户连接远程宿主后，本机虚拟机列表会被远程列表替换；要操作本机时必须切回本机。这个模型无法同时呈现本机和多台远程 Hyper-V 宿主，也使页面选择、后端操作目标、重连、控制台和写入保护都依赖同一个全局状态。

用户实际需要在同一个工作区持续管理本机，并按需连接多台局域网宿主。单台远程宿主掉线或断开不应清空其他宿主的数据，也不应阻止其他宿主继续读写。当前独立的远程详情样式、常驻“切回本机”与“配置预检”入口、诊断结束后一次性显示的日志，同样不能满足已确认的交互需求。

如果继续扩展单活动宿主模型，宿主切换和结果归属判断会散落到每个 VM 命令与页面，增加跨宿主误操作、旧异步结果污染和界面状态不一致的风险。

## Solution

ExHyperV 改为“固定本机会话 + 多个远程会话”的多宿主管理模型。本机始终作为“虚拟机”页面第一组存在，用户可以同时连接多台已保存的远程宿主；每台宿主独立维护连接状态、虚拟机集合、能力、写操作、控制台窗口、诊断日志和自动重连。

所有 VM 读写和控制台操作都由宿主身份与虚拟机身份共同确定，不再根据页面当前选中项或全局活动宿主决定目标。单台宿主掉线时只保留并冻结该宿主的旧数据，其他宿主继续工作；用户主动断开时只移除目标远程宿主的虚拟机分组，已保存的主机配置仍然保留。

“主机连接”页面以连接/断开为核心：连接时自动执行最新诊断，WMI/DCOM 成功即可加入管理工作区，TCP 2179 失败只影响控制台。日志 Tab 实时显示当前选中宿主的脱敏日志。设置修复入口仅在诊断发现可处理问题时出现，仍使用只读检测、变更预览和精确中文 `确认` 的安全流程。

本机与远程宿主复用现有 WPF-UI 主题、状态图标、按钮样式和虚拟机详情布局。能获取的数据保持相同位置；永久不支持的远程功能隐藏，暂时不可用的操作置灰并通过 Tooltip 解释原因。

## User Stories

1. 作为 ExHyperV 用户，我希望本地计算机始终显示在虚拟机工作区，以便随时管理本机虚拟机。
2. 作为 ExHyperV 用户，我希望本地计算机固定排在宿主列表第一组，以便每次都能快速定位。
3. 作为 ExHyperV 用户，我希望同时连接多台已保存的局域网 Hyper-V 宿主，以便在一个应用中管理多台计算机。
4. 作为 ExHyperV 用户，我希望每台已连接宿主拥有独立的虚拟机分组，以便清楚识别每台虚拟机的所属宿主。
5. 作为 ExHyperV 用户，我希望远程宿主按连接顺序稳定排列，以便列表不会无故跳动。
6. 作为 ExHyperV 用户，我希望应用重启后只自动加载本机，以便不会未经确认重新连接远程计算机。
7. 作为 ExHyperV 用户，我希望保存的远程主机配置在重启后继续存在，以便需要时手动重新连接。
8. 作为 ExHyperV 用户，我希望选择主机只改变当前查看的详情和日志，以便浏览行为不会改变后端操作目标。
9. 作为 ExHyperV 用户，我希望不再看到“切回本机”按钮，以便界面符合本机始终在线的实际模型。
10. 作为 ExHyperV 用户，我希望连接远程宿主不会清空本机或其他远程宿主的虚拟机列表，以便保持并行工作状态。
11. 作为 ExHyperV 用户，我希望断开远程宿主时只移除该宿主的虚拟机分组，以便其他宿主保持不变。
12. 作为 ExHyperV 用户，我希望断开连接后仍保留该宿主的保存配置，以便以后可以重新连接。
13. 作为 ExHyperV 用户，我希望虚拟机身份同时包含宿主和虚拟机标识，以便相同名称或相同 GUID 不会造成跨宿主误操作。
14. 作为 ExHyperV 用户，我希望每次只能选择同一宿主的虚拟机，以便批量操作不会跨越权限和连接边界。
15. 作为 ExHyperV 用户，我希望选择另一宿主的虚拟机时自动清除原组选择，以便当前操作目标保持明确。
16. 作为 ExHyperV 用户，我希望批量确认显示宿主名称和目标数量，以便执行前能确认影响范围。
17. 作为 ExHyperV 用户，我希望危险操作确认显示宿主名称和虚拟机名称，以便避免改错机器。
18. 作为 ExHyperV 用户，我希望点击“连接到此主机”后自动执行最新诊断，以便连接不依赖过期检测结果。
19. 作为 ExHyperV 用户，我希望连接期间按钮显示忙碌状态，以便知道请求正在处理。
20. 作为 ExHyperV 用户，我希望连接成功后按钮变为“断开”，以便同一位置表达当前可执行动作。
21. 作为 ExHyperV 用户，我希望 WMI/DCOM 成功后立即加载远程虚拟机，以便控制台端口故障不阻塞管理功能。
22. 作为 ExHyperV 用户，我希望 TCP 2179 失败时会话显示为部分可用，以便知道管理功能仍然正常。
23. 作为 ExHyperV 用户，我希望 TCP 2179 失败时控制台按钮保持可见但置灰，以便理解功能存在和不可用原因。
24. 作为 ExHyperV 用户，我希望错误密码被明确提示为用户名或密码错误，以便直接修正凭据。
25. 作为 ExHyperV 用户，我希望有效身份但权限不足被提示为 WMI/Hyper-V 权限不足，以便区别于密码错误。
26. 作为 ExHyperV 用户，我希望网络、WMI/DCOM、权限和 TCP 2179 错误分别分类，以便采取正确的修复措施。
27. 作为 ExHyperV 用户，我希望当前 Windows 身份继续作为已有的连接方式，以便域或已授权环境无需重复配置。
28. 作为 ExHyperV 用户，我希望显式凭据可以选择记住或仅用于本次连接，以便平衡便利性和安全性。
29. 作为 ExHyperV 用户，我希望记住的密码继续只存入 Windows 凭据管理器，以便配置和日志不出现明文秘密。
30. 作为 ExHyperV 用户，我希望可以保存多个拥有不同凭据的宿主，以便管理不同权限边界。
31. 作为 ExHyperV 用户，我希望单台远程宿主意外掉线时保留其最后一次成功数据，以便继续查看故障前状态。
32. 作为 ExHyperV 用户，我希望旧数据有明确标记，以便不会误认为它仍然实时。
33. 作为 ExHyperV 用户，我希望掉线宿主的写操作立即禁用，以便不会向失效会话提交变更。
34. 作为 ExHyperV 用户，我希望掉线宿主自动重连，以便短暂网络波动后恢复工作。
35. 作为 ExHyperV 用户，我希望每台宿主只有一个重连任务，以便避免并发连接和状态竞争。
36. 作为 ExHyperV 用户，我希望宿主 A 重连时宿主 B 仍可正常读写，以便单点故障不会冻结整个应用。
37. 作为 ExHyperV 用户，我希望重连成功后刷新该宿主虚拟机和能力状态，以便恢复可信的实时数据。
38. 作为 ExHyperV 用户，我希望主动断开会停止该宿主的自动重连，以便应用尊重我的明确操作。
39. 作为 ExHyperV 用户，我希望某台宿主存在写操作时其断开按钮置灰，以便避免中断正在提交的变更。
40. 作为 ExHyperV 用户，我希望断开按钮的 Tooltip 说明正在执行写操作，以便知道何时可以重试。
41. 作为 ExHyperV 用户，我希望没有控制台和写操作时可以直接断开，以便减少不必要的确认。
42. 作为 ExHyperV 用户，我希望目标宿主存在控制台窗口时看到确认弹窗，以便了解断开会关闭哪些会话。
43. 作为 ExHyperV 用户，我希望确认断开后只关闭目标宿主的控制台窗口，以便其他宿主控制台不受影响。
44. 作为 ExHyperV 用户，我希望取消断开确认后所有窗口和连接保持原状，以便取消操作没有副作用。
45. 作为 ExHyperV 用户，我希望本机和远程虚拟机详情使用相同字体和颜色，以便页面视觉一致。
46. 作为 ExHyperV 用户，我希望本机和远程虚拟机按钮使用相同样式，以便相同操作具有相同识别方式。
47. 作为 ExHyperV 用户，我希望连接状态复用现有绿色勾、红色叉、黄色点和红色点，以便不需要学习新的状态语言。

## Implementation Decisions

- 第一阶段已经实现的 WMI/DCOM 管理通道、TCP 2179 控制台通道、IPv4 范围、主机配置、Windows 凭据管理器、诊断、配置和回滚安全约束继续有效。
- 单一活动宿主决策被“固定本机会话 + 多个远程会话”取代。本机始终存在，远程会话由用户手动连接，不在应用启动时自动恢复。
- 建立宿主会话注册表作为多宿主运行时状态的唯一来源。注册表负责本机会话、远程会话集合、稳定顺序、连接状态、通道状态、每宿主代次、旧数据、能力、写计数和重连生命周期。
- 主机列表中的选中项只属于界面状态。选中主机可以改变详情与日志过滤，但不能改变 VM 读写或控制台的后端目标。
- 宿主使用稳定的宿主身份。本机拥有明确的本机身份；远程宿主身份由保存配置的稳定 ID 派生，不使用显示名或 IPv4 作为唯一键。
- 虚拟机身份由宿主身份和虚拟机 ID 组成。任何读取、写入、选择、确认和控制台会话都必须保留这两个维度。
- 每台宿主独立维护会话代次。重新连接、重连成功或断开只使该宿主的旧结果失效，不影响其他宿主。
- 现有活动宿主协调接口演进为多宿主会话注册接口。迁移期间可以短暂存在兼容实现，但交付时删除全局活动宿主语义，不长期维护双模型。
- 建立显式宿主操作路由模块，集中处理会话捕获、WMI 上下文解析、每宿主写租约、代次校验、取消、结果应用和连接丢失报告。
- VM 功能模块不再自行读取当前活动宿主，也不根据页面选中项推断目标。所有 VM 读写接收宿主身份或完整虚拟机身份。
- 每宿主写租约只阻止目标宿主断开或接受冲突操作，不建立全局写冻结。
- 多宿主会话注册表以不可变快照发布状态。页面一次收到完整的新状态，不自行拼接连接、能力和重连字段。
- 连接流程总是执行最新诊断。WMI/DCOM 成功是建立管理会话的必要条件；TCP 2179 独立决定控制台能力。
- 显式凭据验证失败映射为无效凭据；身份可用但 WMI/Hyper-V 授权不足映射为拒绝访问；网络、RPC、命名空间和 TCP 2179 使用独立分类。
- 新会话使用准备后原子提交。诊断、连接或基础快照加载失败时，不发布半完成的 VM 分组。
- 正常连接状态至少区分本机已连接、远程连接中、远程已连接、部分可用、重连中、断开和失败。
- 意外连接丢失只冻结目标宿主写操作，保留最后成功数据并标记为旧数据，然后启动该宿主唯一的自动重连循环。
- 用户主动断开取消目标宿主的刷新、连接和重连任务，释放其管理连接并移除 VM 分组，但不删除保存配置。
- 每台宿主拥有独立 VM 分组视图模型，负责该宿主的状态、能力、VM 集合、最后刷新时间、旧数据标志和刷新生命周期。
- 虚拟机页面负责宿主分组排序、搜索、当前详情和跨组选择规则，不负责 WMI 连接或后端路由。
- 本机组固定第一且不可移除。远程组按成功连接顺序加入；用户主动断开后移除。
- 跨组选择通过单一当前宿主选择域约束。选择新组中的项目会清除原组选择，批量命令只接收一个宿主身份。
- 本机和远程虚拟机详情合并为统一模板。相同数据使用相同布局、主题颜色和按钮样式。
- 能力状态区分可用、暂时不可用和永久不支持。暂时不可用的命令保留、置灰并显示原因；永久依赖本机硬件、本机文件系统或未提供远程实现的项目在远程详情中隐藏。
- 所有主题前景、背景、边框和状态颜色复用现有 WPF-UI 资源与统一状态画刷，不增加硬编码黑色或远程专属颜色体系。
- 主机连接页移除“切回本机”。远程主按钮根据会话状态显示连接、正在连接或断开。
- 目标宿主存在写租约时禁用断开，并通过 Tooltip 显示原因。
- 建立按宿主维护的控制台窗口注册表。控制台创建时登记、关闭时注销，窗口身份由宿主和虚拟机共同确定。
- 没有写操作和控制台窗口时直接断开。存在目标宿主控制台窗口时先确认；确认后关闭目标宿主全部控制台并断开，取消不改变任何状态。
- 日志在分发前生成结构化、不可变、已脱敏的条目，同一个条目同时提供给滚动文件写入和实时日志 Feed。
- 实时日志 Feed 按宿主提供有界历史和订阅。默认每宿主保留最近 2,000 条内存日志，不改变磁盘日志容量。
- 没有远程宿主上下文的应用级日志归入应用或本机范围，不混入任意远程宿主日志。
- 诊断、预检、配置、会话、重连和 VM 操作都携带结构化宿主身份。诊断步骤产生时立即发布，不等待完整报告完成。
- 日志 Tab 订阅当前选中宿主。切换选择时更换过滤范围；新条目默认跟随，用户向上滚动后暂停，并通过“回到最新”图标恢复。
- `logs` 目录、UTF-8 无 BOM、`ExHyperV.log` 与 `ExHyperV.1.log`、每份 100 MiB 和总量约 200 MiB 的磁盘策略保持不变。
- 顶部常驻配置预检入口被按需修复动作取代。只有最新诊断产生可处理发现时才展示“检查并修复设置”。
- 按需修复复用现有只读预检、最小变更规划、变更预览、精确中文 `确认`、执行、复检和回滚机制。
- Public 网络修改必须由用户从检测到的候选网络列表中明确选择。未选择或未输入精确 `确认` 时不得执行任何修改。
- 实施采用替换式迁移：先建立新身份与注册表行为，再迁移操作路由、VM 分组、控制台和日志，最后删除旧活动宿主接口、分叉详情模板和只验证单活动宿主的测试。

## Testing Decisions

- 最高层主要测试接缝是宿主会话注册表。测试通过连接、断线、重连、断开命令和不可变快照验证用户可观察行为，不断言内部字典、锁或任务对象。
- 显式宿主操作路由是第二个必要接缝，用于验证本机与远程 WMI 上下文选择、每宿主写租约、代次拒绝和连接丢失传播。测试不直接穿透路由检查 WMI 缓存实现。
- 控制台窗口注册表和实时日志 Feed 分别覆盖窗口生命周期与实时流行为，这些行为不能仅通过会话快照完整表达。除这些已确认接缝外不增加仅为 mock 而存在的接口。
- 测试优先复用现有会话切换、VM 操作、重连、控制台、诊断、能力、预检和配置测试中的生产适配器与确定性替身。
- 旧的单活动宿主测试在新注册表行为被覆盖后删除或改写，不在新测试外再维护一层兼容断言。
- 必测启动场景包括：没有保存配置、有多个保存配置、应用启动后均只有固定本机会话和本机 VM 分组。
- 必测连接场景包括：本机与两个远程会话并存、当前 Windows 身份成功、显式凭据成功、错误密码、权限不足、WMI 失败、WMI 成功且 2179 失败、取消和重复连接。
- 必测隔离场景包括：宿主 A 写入时宿主 B 可读写、宿主 A 掉线不改变宿主 B、宿主 A 旧代次结果不能更新 A 新会话或宿主 B。
- 必测 VM 分组场景包括：本机固定第一、远程按连接顺序出现、主动断开只移除目标组、重连保留旧组、相同 VM 名称不会串组。
- 必测选择场景包括：同组单选和批量选择、跨组选择清除原选择、命令永远只接收单一宿主身份。
- 必测写操作场景包括：目标宿主写租约存在时断开禁用、其他宿主断开不受影响、写完成后目标宿主可以断开。
- 必测断开场景包括：无控制台直接断开、有控制台确认并关闭目标窗口、取消确认零副作用、主动断开停止自动重连。
- 必测控制台场景包括：窗口按宿主和 VM 登记、关闭时注销、2179 失败时拒绝打开且原因明确、断开宿主 A 不关闭宿主 B 窗口。
- 必测故障场景包括：旧数据标记、目标宿主写入冻结、每宿主唯一重连任务、有上限退避、手动立即重试、重连成功恢复能力和数据。
- 必测能力场景包括：相同本机/远程数据共享展示、临时不可用按钮置灰并说明、永久不支持项在远程详情隐藏、主题状态视觉一致。
- 必测错误分类包括：错误密码为无效凭据、有效身份无权限为拒绝访问、WMI/DCOM 通道错误与 TCP 2179 通道错误分别呈现。
- 必测实时日志场景包括：逐条发布、按宿主过滤、选择切换、内存上限、磁盘和 UI 使用同一脱敏内容、敏感字段名和值均不能泄露。
- 日志滚动测试继续验证程序目录 `logs`、单文件 100 MiB、只保留两份、并发写入、重启续写和 UTF-8 无 BOM。
- 必测日志交互包括：默认跟随最新、用户向上滚动后暂停、新条目不改变阅读位置、点击“回到最新”恢复跟随。
- 必测按需修复场景包括：无可处理发现时不显示入口、有发现时显示、只读阶段零修改、Public 网络必须列表选择、非精确 `确认` 零修改、执行后复检和回滚材料完整。
- WPF ViewModel 测试验证命令状态、按钮文字、Tooltip、分组顺序、状态图标语义和确认内容；业务正确性不依赖像素截图。
- UI 人工验收覆盖亮色与暗色、宽窗口与窄窗口，重点检查标题颜色、工具栏对齐、统一详情模板、分组列表、日志滚动和断开弹窗，无重叠或硬编码黑色。
- 确定性测试必须模拟本机加两台远程宿主并行。首轮真实环境至少验证本机加一台受控远程宿主；有第二台受控宿主时补充真实并行证据，但不阻塞第一轮交付。
- 受控宿主验收继续把配置修改、回滚、VM 写操作和故障注入放在独立的精确中文 `确认` 开关后，不因运行普通集成测试而触发。
- 产品构建与集成运行串行执行，避免共享中间输出造成非产品故障。
- 完成门槛包括确定性测试、Release 构建、XAML 解析、UTF-8 无 BOM、差异检查和受控宿主证据全部通过。

## Out of Scope

- IPv6、主机名/DNS 连接、mDNS、Active Directory 自动发现和局域网扫描。
- 应用启动时自动恢复或自动连接上次使用的远程宿主。
- WinRM、PowerShell Remoting、SSH、代理服务或自定义 RPC 管理协议。
- Hyper-V 集群、故障转移群集、Replica、实时迁移和跨宿主虚拟机迁移。
- 跨宿主批量选择、批量启停或跨宿主事务。
- 自动复制主机配置或凭据到其他计算机或云端。
- 为依赖本机硬件、本机文件系统、注册表、HCS、USB 或 PCIe 设备的功能伪造远程等价实现。
- 修改 Windows 全局动态 RPC 端口范围。
- 无确认地修改 Public 网络、账户组成员关系、防火墙或其他目标机设置。
- 将密码、令牌或凭据对象写入配置、日志、异常、实时 Feed 或回滚脚本。
- 改变 TCP 2179 的控制台协议、增强会话语义或 RDP 控件实现。
- 更改磁盘日志为超过两份或总量超过约 200 MiB 的保留策略。
- 为实时日志增加远程上传、集中式日志服务器、全文索引或复杂查询语言。
- 在第一轮交付中重构与多宿主路由无关的页面和本机功能。

## Further Notes

- 本规格只取代第一阶段规格中的“同一时刻只有一台活动宿主”及其宿主切换交互；既定协议、安全、凭据、配置和回滚约束继续有效。
- 当前代码已经具备活动宿主协调、连接候选、写租约、旧代次拒绝、自动重连、能力矩阵和远程 WMI 上下文。这些实现应演进为每宿主状态，不需要另建第二套远程管理协议。
- 当前 VM 页面、VM 操作和控制台捕获均依赖全局活动宿主，是迁移的主要风险。迁移必须先建立显式宿主身份，再改调用方，不能只改变列表外观。
- 当前日志已具备滚动文件与集中脱敏。实时 Feed 应消费同一个已脱敏结构化条目，避免在 UI 侧复制敏感信息判断。
- 当前配置预检与确认执行流水线已经完整实现。本次只改变入口出现条件和诊断上下文，不重新设计远程配置脚本。
- 设计遵循 KISS：取消全局宿主切换，所有操作显式指向宿主；遵循 YAGNI：不加入发现、启动恢复或跨宿主编排；遵循 DRY：统一详情模板、操作路由和日志脱敏；遵循 SOLID：会话注册、操作路由、VM 分组、控制台窗口和日志分别承担明确职责。
